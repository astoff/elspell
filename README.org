#+title: Elspell — Hunspell-compatible spell checker in pure Emacs Lisp

#+begin_quote
[!NOTE]
This package includes LLM-generated code.
#+end_quote

Elspell is a rewrite of Hunspell/Nuspell in pure Emacs Lisp.  It is
nearly fully compatible with Hunspell and typically achieves 10% to
30% of the native C++ library performance.

This package only supplies a spellchecking API.  For an actual user
interface, see [[https://github.com/astoff/jit-spell][jit-spell]].

You will also need some Hunspell dictionaries (=*.aff= and =*.dic=
files).  They are probably already installed on your system or
available from the package manager.  Alternatively, you can get
dictionaries from the [[https://github.com/LibreOffice/dictionaries][LibreOffice dictionaries]] repository and place
them in one of the directories listed in ~elspell-dictionary-path~,
for instance =~/.local/share/hunspell/=.

** Motivation

Currently, the options for accessing a spellchecker from Emacs are:

- Talking to an external program (GNU Aspell, Hunspell, etc.) through
  a subprocess, via the =ispell -a= pipe interface.  This is what good
  old ispell.el, Flyspell and jit-spell traditionally use.
- Compiling a third-party dynamic module that links against a
  spellchecking library, which is what [[https://github.com/minad/jinx][jinx]] does.

The problem with the =ispell -a= interface is that one cannot opt out
of computing correction suggestions for every incorrect word, which is
three orders of magnitude slower than just checking whether a word is
correct.  This makes it a poor fit for on-the-fly checking of a whole
buffer, where most of the work should be cheap yes/no checks and
suggestions are only needed when the user actually asks for them.

Dynamic modules solve the performance problem, but require every user
to have a working compiler toolchain and the development headers of
the spellchecking library.

Other conceivable approaches are:
- Linking Emacs itself against a spellchecking library.  This seems to
  have been ruled out, judging by the fact that it never happened.
- A foreign function interface (FFI) in Emacs, which would allow
  calling Hunspell or a similar library directly.  Such a feature has
  been rejected by the Emacs maintainers.
- A small helper program, talking to Emacs over a pipe with a better
  protocol than =ispell -a=.  This can be done, and with prebuilt
  binaries for every OS it could potentially "just work".

Apart from that, a pure Emacs Lisp implementation is really the only
option left for a good spellchecking experience that works out of the
box, with no distribution hurdles.

Moreover, this package is an interesting experiment in how far Emacs
Lisp can be pushed.  It performs better than I would have guessed.

** Compatibility with Hunspell

We aim to be compatible with the widely available Hunspell dictionary
format and, within reasonable bounds, with Hunspell's behavior.  Among
our benchmark dictionaries, while testing on a classical text of each
language, we
- fully agree with Hunspell on German (DE), English (US) and
  Portuguese (BR), and
- diverge on 0.56% of words in Korean and 0.09% of words in Hungarian.

Some key discrepancies currently are:
- We use Emacs's built-in casing logic, which, depending of your
  configuration, may disagree with Hunspell's handling of ı (dotless
  i) and İ in Turkic languages.
- We reject words like STRAßE (that's all caps with a lowercase sharp
  s inside), while Hunspell accepts it.
- The `COMPLEXPREFIXES` feature is unsupported.
- Phonetic suggestion are not implemented.

Of the 82 dictionaries available in Debian, we can load and use 79;
one, Central Kurdish, uses `COMPLEXPREFIXES`, and two, Bengali and
Mongolian, seems to some malformed rules.

** Development

The Makefile has targets for the usual development tasks:

- ~make~ byte-compiles the package.
- ~make hunspell nuspell~ fetches the reference versions of those
  programs.
- ~make tests~ runs the test suite, which includes the Hunspell tests.
- ~make compare~ checks that Elspell and Hunspell find the same
  misspelled words in Emacs's =etc/HELLO= (or ~COMPARE_FILE~), for
  every dictionary distributed in Debian.
- ~make bench~ runs the benchmarks shown above, on classic texts
  downloaded from Project Gutenberg and Wikisource.
